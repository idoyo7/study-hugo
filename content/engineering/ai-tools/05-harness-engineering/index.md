# 05 · 하네스 엔지니어링 — AI가 일하는 방식을 개선하기

Lilian Weng은 하네스 개선 연구를 통해 **AI 자기개선의 가능성과 한계**를 살펴봅니다.

> 원문: Lilian Weng, [Harness Engineering for Self-Improvement](https://lilianweng.github.io/posts/2026-07-04-harness/), 2026-07-04. 핵심 논지를 한국어로 요약하고, 주요 연구는 논문을 함께 확인했습니다. 아래 도식 두 장은 개념을 설명하기 위해 새로 그렸습니다.

## 1. 하네스는 모델의 실행을 관리한다

**하네스(harness)**는 모델의 도구 호출·컨텍스트·기록·평가·권한을 관리하는 실행 시스템입니다. 주요 패턴은 다음과 같습니다.

- **반복 실행:** 계획·실행·검사·수정을 반복합니다.
- **파일로 남기는 기억:** 작업 기록을 저장하고 필요할 때 읽습니다.
- **관찰 가능한 병렬 작업:** 하위 에이전트와 백그라운드 작업의 상태·로그를 추적합니다.

## 2. 개선 대상이 프롬프트에서 실행 코드로 넓어진다

원문이 묶어 보여 주는 연구는 **무엇을 바꾸는가**로 나누면 읽기 쉽습니다. 아래는 주요 논문을 바탕으로 정리한 비교입니다.

| 연구 | 바꾸는 대상 | 핵심 방법 |
|---|---|---|
| [ACE](https://arxiv.org/abs/2510.04618) | 모델에 전달할 지식과 전략 | 실행 결과에서 교훈을 추출하고, 항목별로 추가·수정하는 작업 지침을 유지합니다. 전체를 반복해서 요약하며 세부 지식이 사라지는 문제를 줄입니다. |
| [MCE](https://arxiv.org/abs/2601.21557) | 컨텍스트와 그것을 만드는 방법 | 안쪽에서는 작업에 쓸 컨텍스트를 다듬고, 바깥쪽에서는 컨텍스트를 구성하는 스킬을 개선합니다. |
| [ADAS](https://arxiv.org/abs/2408.08435) | 에이전트의 워크플로 | 메타 에이전트가 기존 설계 기록을 참고해 새 에이전트를 코드로 만들고 평가합니다. 프롬프트·도구·제어 흐름이 탐색 대상입니다. |
| [Meta-Harness](https://arxiv.org/abs/2603.28052) | 정보를 저장·조회·제시하는 하네스 코드 | 코딩 에이전트가 이전 후보의 코드·점수·실행 기록을 파일에서 찾아보고 새 하네스를 제안합니다. |
| [STOP](https://arxiv.org/abs/2310.02304) | 프로그램을 개선하는 프로그램 | 개선기가 다른 프로그램을 수정하고 평가하다가, 자기 자신의 개선 코드에도 같은 절차를 적용합니다. 모델 가중치는 고정합니다. |

ACE와 MCE의 차이가 특히 중요합니다. ACE는 실행·성찰·정리라는 정해진 절차 안에서 지침을 축적합니다. MCE는 그 지침을 **어떤 방식으로 만들지**까지 탐색합니다. 내용의 수정에서 수정 방법의 개선으로 범위가 넓어지는 셈입니다. [ACE 논문](https://arxiv.org/abs/2510.04618), [MCE 논문](https://arxiv.org/abs/2601.21557)

## 3. 실행 루프 바깥에서 하네스를 평가하고 고친다

한 작업 안에서 오류를 고치는 것과, 다음 작업에 쓸 에이전트 자체를 고치는 것은 구분할 수 있습니다. Meta-Harness의 바깥 루프는 후보 하네스를 만들고, 실행 결과를 모아, 다음 후보를 찾는 데 활용합니다. **이전 시도의 코드와 실패 기록이 다음 수정의 근거가 됩니다.** [Meta-Harness 논문](https://arxiv.org/abs/2603.28052)

진화적 탐색은 이 과정을 여러 후보에 적용합니다. [Darwin Gödel Machine(DGM)](https://arxiv.org/abs/2505.22954)은 에이전트 후보들을 보관하고, 하나를 골라 하네스 코드를 수정한 뒤 코딩 벤치마크로 검사합니다. 후보들을 남겨 두면 서로 다른 개선 경로를 탐색할 수 있습니다. 이 연구에서 바뀌는 것은 모델 주변의 코드이며, 기반 모델의 가중치는 고정되어 있습니다.

수정의 근거를 추적하는 방법도 연구 대상입니다. [AHE](https://arxiv.org/abs/2604.25850)는 실행 기록에서 실패 원인을 찾고, 수정할 구성요소와 예상 효과를 명시한 뒤 다음 평가로 확인합니다. 단순히 점수가 올랐는지에 더해, **어느 변경이 어떤 실패를 줄였는지**를 확인하려는 설계입니다.

## 4. 하네스 개선과 모델 학습은 다른 범위의 변화다

STOP과 DGM은 모델 가중치를 바꾸지 않고 주변 프로그램을 개선합니다. 반면 [SIA](https://arxiv.org/abs/2605.27276)는 작업을 실행하는 에이전트, 하네스를 제안하는 메타 에이전트, 다음 갱신을 정하는 피드백 에이전트를 둡니다. 실행 기록을 보고 하네스를 바꿀지 모델 가중치를 갱신할지 선택하는 초기 연구입니다.

Weng은 SIA의 모델 간 능력 차이와 약한 비교 기준 때문에 근거가 잠정적이라고 봅니다. 하네스 중심의 단기 재귀적 자기개선(RSI) 경로도 저자의 **전망**입니다. [원문: 가중치와의 공동 최적화](https://lilianweng.github.io/posts/2026-07-04-harness/#joint-optimization-with-model-weights)

## 5. 남은 어려움은 무엇을 성공으로 볼지에 있다

원문이 꼽는 한계는 다음과 같습니다.

- **평가:** 연구의 새로움과 장기 가치는 채점하기 어렵습니다.
- **기억:** 중요한 맥락을 오래 보존해야 합니다.
- **실패:** 부정적 결과를 남겨야 반복을 줄입니다.
- **다양성:** 비슷한 해법에 탐색이 몰릴 수 있습니다.
- **보상 해킹:** 평가의 허점을 이용할 수 있습니다.
- **장기 성과:** 테스트 통과가 유지보수성을 보장하지는 않습니다.

저자는 평가기·권한 통제를 개선 대상에서 분리하고, 별도 과제와 기록 검토로 확인할 것을 제안합니다. [원문: 남은 과제](https://lilianweng.github.io/posts/2026-07-04-harness/#future-challenges)
