# 두 클러스터는 따로 수렴하고, 필요한 것만 건넌다

이 홈랩에는 물리적으로 떨어진 Kubernetes 클러스터가 두 개 있습니다. 현재 집의 **hub**에는 Synology NAS와 중앙 서비스가 있고 본가의 **edge**에는 영속 스토리지가 없습니다. 두 집 사이를 오가는 것은 인증된 연결 둘뿐입니다.

그렇다고 hub가 edge를 지휘하는 구조는 아닙니다. 두 클러스터의 ArgoCD는 같은 GitOps repo에서 각자의 선언을 직접 가져옵니다. hub가 멈춰도 edge는 GitHub만 볼 수 있으면 계속 배포됩니다. 둘이 런타임에 공유하는 것은 중앙에 둘 이유가 분명한 두 기능뿐입니다.

그림은 세 영역으로 읽습니다. 왼쪽은 상태를 보유한 hub, 오른쪽은 저장소가 없는 edge, 가운데는 `두 집 사이 · 인증된 연결` 경계입니다. 위쪽 GitOps repo는 두 클러스터가 각자 당겨가는 공통 정본일 뿐, 한 클러스터를 다른 클러스터에 종속시키지 않습니다.

가운데 경계를 가로지르는 런타임 의존성은 둘입니다.

1. **remote write** — edge vmagent가 수집한 메트릭을 hub VictoriaMetrics로 보냅니다.
2. **OIDC** — edge ArgoCD가 hub Keycloak에 사람 인증을 위임합니다.

배포·접근·관측을 한 그림에 모두 넣었지만 각 평면의 내부 구현은 펼치지 않았습니다. 전체 지도는 어디에 무엇이 있고 어느 장애가 반대편까지 번지는지만 보여줍니다. 인증 절차와 메트릭 수집 경로는 각 평면 문서에서 따로 확대합니다.

## 같은 체인, 다른 종착점

두 클러스터는 배포에서 수집까지 같은 모양입니다.

| 단계 | hub | edge |
|---|---|---|
| 선언 | `hub/`를 직접 pull | `edge/`를 직접 pull |
| 배포 | ArgoCD → 워크로드 | ArgoCD → 워크로드 |
| 관측 | 워크로드 → vmagent | 워크로드 → vmagent |
| 저장 | VictoriaMetrics → Synology NAS | 저장하지 않고 hub로 remote write |
| 사람 인증 | 로컬 Keycloak | hub Keycloak에 OIDC 위임 |

체인의 끝에서 둘이 달라집니다. hub는 메트릭과 인증 상태를 품고 NAS에 영속화합니다. edge는 워크로드를 실행하고 메트릭을 수집하지만 복원해야 할 영속 상태를 남기지 않습니다.

## 중앙화하되, 장애까지 묶지는 않는다

이 구조에서는 hub가 고장 나도 edge의 기능이 전부 멈추지는 않습니다. 이미 실행 중인 워크로드와 GitOps 수렴은 계속됩니다. 대신 edge 메트릭의 원격 저장과 새로운 ArgoCD 로그인은 멈춥니다. 중앙화의 편익과 장애 범위를 두 연결에만 가뒀습니다.

| hub에서 멈춘 것 | edge에 생기는 영향 | 계속되는 것 |
|---|---|---|
| VictoriaMetrics 수신 경로 | 메트릭 전송 지연·버퍼링 | 워크로드 실행, 로컬 수집 |
| Keycloak | 새 ArgoCD 로그인 불가 | 기존 워크로드, GitOps sync |
| hub 클러스터 전체 | 위 두 의존성 사용 불가 | GitHub 기반 edge 배포 |

세부 구현은 [관측 평면]({{< relref "../02-observability/index.md" >}})과 [배포·접근 평면]({{< relref "../03-deployment-access/index.md" >}})에서 이어집니다.
